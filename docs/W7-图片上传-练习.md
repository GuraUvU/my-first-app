# W7 练习：给留言加图片

> 已定的四个设计决定：
> 1. **公开 bucket**（图片 URL 直接可看，简单）
> 2. **路径 `{user_id}/{随机名}.png`**（策略能绑定用户 + 名字不可猜）
> 3. **单独 `images` 表，一对多**（一条留言可带多张图）
> 4. **W7 先不做删除**
>
> 分两段：**先建后端（bucket + 表 + 策略），验过再写前端**。

## 这次的新东西

| 概念 | 一句话 |
|---|---|
| Storage（对象存储） | 存文件的地方，和数据库是**两套独立权限** |
| Storage policy | 谁能往哪个"目录"传文件，单独写一遍 |
| `upload()` | supabase-js 上传文件，返回 `{ data: { path }, error }` |
| `getPublicUrl()` | 把存储路径换成可访问的 URL（公开 bucket 才有） |
| `.select().single()` | 插入后**把刚插入的那行拿回来**（之前你只检查 error） |
| 嵌套 select | `select("id, content, images(path)")` 一次查出留言 + 它的图片 |

# 第一步：建 bucket（网页操作）

Storage → **New bucket**

| 字段 | 填什么 |
|---|---|
| Name | `message-images` |
| Public bucket | **✓ 勾上** |
| File size limit | `2 MB`（或 2097152 字节） |
| Allowed MIME types | `image/png, image/jpeg, image/webp` |

> **为什么大小和类型必须在这里配**：前端的 `accept="image/*"` 和 `maxLength` 只是提示，用户改一下 DOM 就绕过了。bucket 上的限制是**服务端**的，绕不过去。

**验收**：Storage 页面出现一个叫 `message-images` 的公开 bucket。

# 第二步：建表 + 写策略（SQL Editor，一段一段跑）

## 2.1 Storage 策略

```sql
-- 登录用户只能往自己 id 开头的目录里传
create policy "登录用户可以上传到自己的目录"
on storage.objects for insert
to authenticated
with check (
  bucket_id = 'message-images'
  and (storage.foldername(name))[1] = auth.uid()::text
);

-- 任何人（含未登录）都能读这个 bucket 里的文件
create policy "任何人都能看图片"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'message-images');
```

**`(storage.foldername(name))[1]`** 是这里最关键的写法：

- `name` 是完整路径，比如 `af2e16ad-....png`
- `storage.foldername(name)` 把它切成数组：`['af2e16ad-...', 'abc.png']`
- `[1]` 是 Postgres 数组的**第一个元素**（从 1 开始，不是 0！）

所以策略的意思是：**你上传的路径，第一段必须等于你自己的 user id**。

## 2.2 images 表

```sql
create table public.images (
  id bigint generated by default as identity primary key,
  message_id bigint not null references public.messages(id) on delete cascade,
  path text not null,
  user_id uuid not null default auth.uid() references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);
```

三个外键相关的东西：

| 写法 | 意思 |
|---|---|
| `references public.messages(id)` | 这条图片记录必须挂在一条真实存在的留言上 |
| `on delete cascade` | 删留言时，它的图片记录自动删（但**文件还在 Storage 里**，这是 W7 不做删除的原因） |
| `default auth.uid()` | 和 messages 一样，写入时自动填当前用户，前端不用传 |

## 2.3 images 的 RLS

```sql
alter table public.images enable row level security;

create policy "任何人都能看图片记录"
on public.images for select
to anon, authenticated
using (true);

create policy "登录用户可以插入自己的图片记录"
on public.images for insert
to authenticated
with check (auth.uid() = user_id);
```

**验收**：Table Editor 出现 `images` 表（0 行），Storage 的 `message-images` 里 **Policies 标签**下能看到两条策略。

# 第三步：改 `MessageCard.tsx`（前端）

## 3.1 类型改一下：留言带上图片

```tsx
type MessageImage = {
  id: number;
  path: string;

type Message = {
  id: number;
  content: string;
  created_at: string;
  images: MessageImage[];      // 🆕 嵌套查出来的是一个数组
};
```

## 3.2 新增两个 state

```tsx
  const [file, setFile] = useState<File | null>(null);
  const [uploading, setUploading] = useState(false);
```

## 3.3 `loadMessages` 改成嵌套查询

```tsx
  async function loadMessages() {
    const { data, error } = await supabase
      .from("messages")
      .select("id, content, created_at, images(id, path)")
      .order("created_at", { ascending: false })
      .limit(10);

    if (error) {
      console.error(error);
      return;
    }
    setMessages((data as Message[]) ?? []);
  }
```

🆕 **嵌套 select**：`images(id, path)` 这一句让 Supabase 顺着外键把关联的图片一起查回来。不用写 JOIN，它替你做了。

查回来的结构：

```json
{ "id": 18, "content": "今天天气不错", "images": [{ "id": 3, "path": "af2e.../abc.png" }] }
```

## 3.4 `sendMessage` 改造成"上传 → 建留言 → 建图片记录"

```tsx
  async function sendMessage() {
    const content = text.trim();
    if (!content) {
      setError("先说点什么吧");
      return;
    }

    setSending(true);
    setError("");

    try {
      // ① 有图就先传文件
      let imagePath: string | null = null;
      if (file) {
        const ext = file.name.split(".").pop()?.toLowerCase() ?? "png";
        const random = crypto.randomUUID();
        imagePath = `${userEmail ? "" : ""}${random}.${ext}`;   // ← 这里要改，见下方说明
        const { error: uploadError } = await supabase.storage
          .from("message-images")
          .upload(imagePath, file, { contentType: file.type });

        if (uploadError) throw uploadError;
      }

      // ② 建留言，并把新行拿回来（需要它的 id）
      const { data: newMessage, error: msgError } = await supabase
        .from("messages")
        .insert({ content })
        .select("id")
        .single();

      if (msgError) throw msgError;

      // ③ 有图就插一条 images 记录
      if (imagePath && newMessage) {
        const { error: imgError } = await supabase
          .from("images")
          .insert({ message_id: newMessage.id, path: imagePath });

        if (imgError) throw imgError;
      }

      setText("");
      setFile(null);
      await loadMessages();
    } catch (err) {
      console.error(err);
      setError("发送失败：" + ((err as Error).message ?? "未知错误"));
    } finally {
      setSending(false);
    }
  }
```

**上面 ① 那行 `imagePath` 我给你留了个坑，你要自己想清楚**：

路径必须是 `{user_id}/{随机名}.{ext}`，但前端怎么拿到 `user_id`？

提示：`supabase.auth.getUser()` 能拿到当前用户对象（含 `id`）。或者用 `(await supabase.auth.getSession()).data.session?.user.id`。

> 注意：`userEmail` 是邮箱，**不是 id**，路径里必须用 id，否则策略 `(storage.foldername(name))[1] = auth.uid()` 对不上，上传会被拒。

## 3.6 渲染图片

```tsx
            {m.images?.length > 0 && (
              <div className="mt-2 flex flex-wrap gap-2">
                {m.images.map((img) => (
                  <img
                    key={img.id}
                    src={supabase.storage.from("message-images").getPublicUrl(img.path).data.publicUrl}
                    alt="留言配图"
                    className="h-24 w-24 rounded-lg object-cover"
                  />
                ))}
              </div>
            )}
```

🆕 `getPublicUrl(path)`：把存储路径换成 URL。**只有公开 bucket 能用**，私有 bucket 要用 `createSignedUrl`（每次生成带过期时间的临时链接）。

1. 登录 → 选一张图 → 输入文字 → 发送
2. 留言出现在列表，**图片显示在留言下方**

4. Storage → `message-images` 里能看到这个文件

# 这一课的四个认知

## 1. 两套权限，都要写

| | 谁管 | 你写了什么 |
|---|---|---|
| 数据库行 | RLS | `images` 表：登录才能插自己的 |
| 文件对象 | Storage policy | 只能写自己 id 目录 |

**少写一个，那半边就是敞开的。** 这是 W7 最重要的认知。

## 2. 公开 bucket 意味着"URL 谁拿到谁能看"

我们的留言板是公开的，所以合理。但如果以后做"私密相册"，就必须是私有 bucket + 签名 URL——那时候 `getPublicUrl` 全部要换成 `createSignedUrl`，且有过期刷新问题。

**先想清楚产品是公开还是私密，再选 bucket。**

## 3. 三步操作不是原子操作

```
① 上传文件  ② 插留言  ③ 插图片记录
```

任何一步失败，前面成功的部分不会自动回滚：

- ① 成功、② 失败 → **孤儿文件**（Storage 里有图，数据库没记录）
- ①② 成功、③ 失败 → **有留言没图**（文件还在）

生产系统要靠"清理任务"兜底，W7 不做——但你得知道它存在。

## 4. `.select().single()` 是拿回插入结果的标准姿势

之前你只检查 `error`，因为不需要知道新行的 id。这次需要（图片要挂到 message_id 上），所以要在 `insert` 后面接 `.select("id").single()`。

**代价**：多一次返回处理。**收益**：不用再查一次数据库。
