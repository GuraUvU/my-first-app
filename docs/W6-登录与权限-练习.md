# W6 第二次：加登录，把"谁都能写"改成"登录才能写"

> 目标：用户能注册 / 登录 / 退出；未登录时看到提示而不是输入框；数据库层面只接受登录用户的写入。
> 分两个阶段，**A 没跑通不要进 B**。总时间约 1.5–2 小时。

---

# 阶段 A：让页面能登录（不用改数据库）

## A1. 关掉邮箱确认（重要，省你一半时间）

Supabase → **Authentication** → **Sign In / Providers**（或 Providers → Email）

找到 **Confirm email**，**关掉**它。

**为什么**：默认开启时，注册后必须点邮件里的链接才能登录。免费项目的邮件发送有频率限制，而且经常进垃圾箱——你会卡在"注册成功了但登不进去"。

⚠️ 关掉意味着**任何邮箱都能注册**（不验证真实性）。学习阶段可以接受，正式产品必须打开，并配自己的 SMTP。

## A2. 新建 `app/components/AuthCard.tsx`

```tsx
"use client";

import { useEffect, useState } from "react";
import { supabase } from "../lib/supabase";

export default function AuthCard() {
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [userEmail, setUserEmail] = useState<string | null>(null);
  const [busy, setBusy] = useState(false);
  const [msg, setMsg] = useState("");

  useEffect(() => {
    // 1) 进来先问一次：现在有人登录吗
    supabase.auth.getSession().then(({ data }) => {
      setUserEmail(data.session?.user.email ?? null);
    });

    // 2) 之后一直听着：登录/退出都会触发
    const { data } = supabase.auth.onAuthStateChange((_event, session) => {
      setUserEmail(session?.user.email ?? null);
    });

    // 3) 清理：组件卸载时取消订阅（和 clearInterval 一个道理）
    return () => data.subscription.unsubscribe();
  }, []);

  async function signUp() {
    setBusy(true);
    setMsg("");
    const { error } = await supabase.auth.signUp({ email, password });
    setBusy(false);
    setMsg(error ? "注册失败：" + error.message : "注册成功，现在可以登录了");
  }

  async function signIn() {
    setBusy(true);
    setMsg("");
    const { error } = await supabase.auth.signInWithPassword({ email, password });
    setBusy(false);
    if (error) setMsg("登录失败：" + error.message);
  }

  async function signOut() {
    await supabase.auth.signOut();
    setMsg("已退出");
  }

  if (userEmail) {
    return (
      <div className="rounded-2xl border border-white/10 bg-white/[0.04] p-6 text-center sm:col-span-3">
        <p className="text-sm text-zinc-300">已登录：{userEmail}</p>
        <button
          type="button"
          onClick={signOut}
          className="mt-3 rounded-full border border-white/15 px-5 py-1.5 text-xs text-zinc-200 transition-colors hover:bg-white/10"
        >
          退出登录
        </button>
      </div>
    );
  }

  return (
    <div className="rounded-2xl border border-white/10 bg-white/[0.04] p-6 sm:col-span-3">
      <h2 className="text-center text-lg font-medium text-white">登录 / 注册</h2>
      <div className="mt-4 space-y-2">
        <input
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          placeholder="邮箱"
          className="w-full rounded-xl border border-white/15 bg-white/5 px-4 py-2.5 text-sm text-zinc-100 outline-none placeholder:text-zinc-500 focus:border-white/30"
        />
        <input
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          placeholder="密码（至少 6 位）"
          className="w-full rounded-xl border border-white/15 bg-white/5 px-4 py-2.5 text-sm text-zinc-100 outline-none placeholder:text-zinc-500 focus:border-white/30"
        />
      </div>
      <div className="mt-3 flex gap-2">
        <button
          type="button"
          onClick={signIn}
          disabled={busy}
          className="flex-1 rounded-xl bg-white px-5 py-2.5 text-sm font-medium text-black transition-opacity hover:opacity-80 disabled:opacity-50"
        >
          登录
        </button>
        <button
          type="button"
          onClick={signUp}
          disabled={busy}
          className="flex-1 rounded-xl border border-white/15 px-5 py-2.5 text-sm text-zinc-200 transition-colors hover:bg-white/10 disabled:opacity-50"
        >
          注册
        </button>
      </div>
      {msg && <p className="mt-3 text-center text-xs text-zinc-400">{msg}</p>}
    </div>
  );
}
```

# 阶段 B：收紧数据库权限

现在数据库还允许匿名写入。这一步把门关上。

## B1. 一条 SQL 干完（SQL Editor 里一次 Run）

```sql
-- 1) 加一列：记录"这条留言是谁写的"
alter table public.messages
  add column user_id uuid references auth.users(id) on delete cascade default auth.uid();

-- 2) 删掉"任何人都能写"的旧策略
drop policy "任何人都能写留言" on public.messages;

-- 3) 只允许登录用户写，且只能以自己身份写
create policy "登录用户可以写留言"
on public.messages for insert
to authenticated
with check (auth.uid() = user_id);

-- 4) 授权
grant insert on public.messages to authenticated;
```

逐个解释：

| 语句 | 作用 |
|---|---|
| `add column user_id ... default auth.uid()` | 新列自动填当前登录用户的 id。前端插入时**不用传**，数据库自己填 |
| `drop policy ...` | 把原来那条 `to anon` 的写入策略删掉 |
| `to authenticated` | 关键词变了：**只有登录用户**（不是匿名访客）满足这条策略 |
| `with check (auth.uid() = user_id)` | 不仅要求登录，还要求"写入的 user_id 必须是你自己"，防止伪造别人的身份 |

# 这次真正学到的四件事

## 1. 认证（Auth）≠ 授权（Authorization）

- **Auth**：你是谁 → 登录，`auth.uid()` 有值
- **Authz**：你能干什么 → 策略里 `to authenticated` + `with check`

Supabase 把两件事分开：`Authentication` 管登录，`Policies` 管权限。任何系统都是这么分的。

## 2. session 存在哪

`supabase.auth.signInWithPassword` 成功后，SDK 把 token 存进 **localStorage**，之后每次请求自动带上。所以刷新页面还是登录状态。

代价：**XSS 攻击可以偷走它**。这也是为什么"别往页面里塞来路不明的脚本"很重要。

## 3. `onAuthStateChange` 是订阅，必须清理

和 `setInterval` 一样：订阅了不取消，组件没了它还在。**凡是"注册了监听"，就一定要在 `return` 里取消。**

## 4. 状态重复的问题（下一步要解决的）

现在 `AuthCard` 和 `MessageCard` **各自**监听登录状态。两个组件还好，等有五个组件都要知道"当前用户是谁"，这种写法就会失控。

标准解法是 **Context**（上下文）——把用户状态放在页面顶层，所有子组件去读。这是 W4"状态归属"的进阶版：

> 多个组件都要用的状态，往它们的**共同父组件**提。

现在先不用改，记住这个味道就行。

# 一个安全边界（提前知道）

即使做了登录，**留言表仍然是"任何人都能读"**。这意味着：

- 用户的邮箱不会暴露（`messages` 表里只有 `user_id`，不是邮箱）✅
- 但留言内容是公开的 ⚠️

如果以后要做"私密留言"，读策略也要加 `auth.uid() = user_id`。这是一个决策点：**公开留言板**（像现在）还是**私人日记**（加读策略）——取决于你要做什么产品。
