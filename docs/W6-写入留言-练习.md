> 目标：页面上能输入一句话 → 点发送 → 存进数据库 → 列表里立刻出现。
> 这次**先不做登录**，让“写入”这件事单独跑通。第二次再加 Auth。

## 这次的新东西

| 概念 | 一句话 |
|---|---|
| INSERT 权限 | 之前只开了 `select`，写数据要单独开 `insert` |
| 受控输入框 | 输入框的值由 state 决定，不是让浏览器自己管 |
| `insert()` | supabase-js 的写入方法，同样返回 `{ error }` |
| 数据库约束 | 长度限制写在数据库里，前端绕不过去 |

# 第 1 步：建表 + 开写权限（网页操作）

Supabase → SQL Editor → New query → 粘贴 → Run（**一次一段，看到 Success 再下一段**）

**① 建表**

```sql
create table public.messages (
  id bigint generated by default as identity primary key,
  content text not null check (char_length(content) between 1 and 200),
  created_at timestamptz not null default now()
);
```

**② 开 RLS + 两条策略**

```sql
alter table public.messages enable row level security;

create policy "任何人都能读留言"
on public.messages for select
to anon, authenticated
using (true);

create policy "任何人都能写留言"
on public.messages for insert
to anon, authenticated
with check (char_length(content) between 1 and 200);
```

**③ 授权**

```sql
grant select, insert on public.messages to anon, authenticated;
```

**验收**：Table Editor 里出现 `messages` 表（目前 0 行）。

### 为什么 `check` 写在建表语句里

```sql
content text not null check (char_length(content) between 1 and 200)
```

这叫**数据库约束**。它保证：

- 空内容写不进去（`not null` + 长度 ≥ 1）
- 超过 200 字写不进去
- **即使用 curl 直接调接口，也绕不过去**

前端校验是“体验”，数据库约束是“底线”。只做前端校验，别人打开控制台就能绕过。

# 第 2 步：新建 `app/components/MessageCard.tsx`

```tsx
"use client";

import { useEffect, useState } from "react";
import { supabase } from "../lib/supabase";

type Message = {
  id: number;
  content: string;
  created_at: string;
};

export default function MessageCard() {
  const [messages, setMessages] = useState<Message[]>([]);
  const [text, setText] = useState("");
  const [sending, setSending] = useState(false);
  const [error, setError] = useState("");

  async function loadMessages() {
    const { data, error } = await supabase
      .from("messages")
      .select("*")
      .order("created_at", { ascending: false })
      .limit(10);

    if (error) {
      console.error(error);
      return;
    }
    setMessages(data ?? []);
  }

  async function sendMessage() {
    const content = text.trim();
    if (!content) {
      setError("先说点什么吧");
      return;
    }

    setSending(true);
    setError("");

    const { error: insertError } = await supabase
      .from("messages")
      .insert({ content });

    setSending(false);

    if (insertError) {
      console.error(insertError);
      setError("发送失败：" + insertError.message);
      return;
    }

    setText("");
    await loadMessages();
  }

  useEffect(() => {
    loadMessages();
  }, []);

  return (
    <div className="rounded-2xl border border-white/10 bg-white/[0.04] p-6 sm:col-span-3">
      <h2 className="text-lg font-medium text-white text-center">留言板</h2>

      <div className="mt-4 flex flex-col gap-2 sm:flex-row">
        <input
          value={text}
          onChange={(e) => setText(e.target.value)}
          maxLength={200}
          placeholder="说点什么…（最多 200 字）"
          className="flex-1 rounded-xl border border-white/15 bg-white/5 px-4 py-2.5 text-sm text-zinc-100 outline-none placeholder:text-zinc-500 focus:border-white/30"
        />
        <button
          type="button"
          onClick={sendMessage}
          disabled={sending}
          className="rounded-xl bg-white px-6 py-2.5 text-sm font-medium text-black transition-opacity hover:opacity-80 disabled:opacity-50"
        >
          {sending ? "发送中…" : "发送"}
        </button>
      </div>

      {error && <p className="mt-2 text-xs text-red-400">{error}</p>}

      <ul className="mt-5 space-y-2">
        {messages.length === 0 && (
          <li className="text-center text-xs text-zinc-500">还没有留言，做第一个吧</li>
        )}
        {messages.map((m) => (
          <li
            key={m.id}
            className="rounded-xl border border-white/10 bg-white/[0.03] px-4 py-2.5 text-sm text-zinc-200"
          >
            {m.content}
            <span className="ml-2 text-[11px] text-zinc-500">
              {new Date(m.created_at).toLocaleString("zh-CN")}
            </span>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

# 三个必须理解的点

## ① 受控输入框

```tsx
<input value={text} onChange={(e) => setText(e.target.value)} />
```

- `value={text}`：输入框显示什么，完全由 state 决定
- `onChange`：用户每敲一个字，把新值存进 state
- 少了 `onChange`，输入框会**锁死**（打不进字）——这是新手最常见的坑

为什么不用 `document.querySelector` 读值？因为 React 的思路是“数据驱动视图”，值就该在 state 里。

## ② `insert` 之后为什么要 `loadMessages()`

写入成功后，数据库里多了一行，但你手里的 `messages` 数组还是旧的。两种选择：

| 做法 | 说明 |
|---|---|
| 重新拉一次（本例） | 简单、可靠，多一次请求 |
| 手动塞进数组 | `setMessages([新消息, ...messages])`，省请求但容易和服务器状态不一致 |

新手阶段**选后者容易出错**（比如服务器给的时间戳、id 你不知道），先老老实实重拉。

## ③ `disabled={sending}` 的必要性

网络慢的时候，用户会连点三次发送按钮 → 插三条一样的留言。

`disabled={sending}` 让按钮在请求期间变灰不可点，是最简单的防重复。这是**所有表单都要做的事**。

# 安全问题（W6 第二次会解决）

现在这条策略：

```sql
create policy "任何人都能写留言"
on public.messages for insert
to anon, authenticated
```

意思是：**任何拿到你 publishable key 的人都能往表里插入数据**。而那个 key 就在你的页面 JS 里。

风险：有人写个脚本，一秒钟插一万条垃圾。

这次的 `check (char_length ≤ 200)` 只是防止“超长”，防不了“很多条”。

所以下一次要做两件事之一：

1. **加 Auth**：改成 `to authenticated`，只有登录用户能写（原计划）
2. **加服务端接口**：前端不直接写库，而是调用你自己的 API（W9 接 LLM 时会用这个模式，因为 LLM 的 key 绝不能放前端）

先记住这个认知：**前端能直接写数据库 = 谁都能写。** 你现在是在学习环境里暂时接受这个风险。
