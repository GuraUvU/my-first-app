## 1. `git push` 了，但 GitHub 上看不到改动

**现象**：改完代码、`git push` 成功，刷新 GitHub 页面还是旧内容。

**原因**：`git push` 只上传「已提交（commit）」的内容。改动还停在「工作区」，根本没进存档。

**正确做法**：

```powershell
git add -A            # 把改动放进待提交区
git commit -m "说明"   # 存档到本地
git push              # 上传已存档的内容
```

**一句话记忆**：**commit 是写日记，push 是把日记本寄出去。没写的那页寄不出去。**

> 当时我怎么想的：不熟悉步骤，以为光push就能更新GitHub

## 2. 网页看着正常，但按钮点了没反应

**现象**：手机上页面显示正常，点按钮没弹窗。电脑上（本地 `npm run dev`）却是好的。

**原因**：静态站上传时漏了一个 JS 文件。HTML 和 CSS 传上去了（所以“看着正常”），但负责交互的 JS 返回的是网页（`text/html`）而不是脚本，浏览器报 `SyntaxError: Unexpected token '<'`，hydration 失败。

**排查方法**：

```powershell
curl -sS -o NUL -w "%{http_code} %{content_type}\n" "https://你的域名/_next/static/chunks/xxx.js"
```

必须是 `application/javascript`。若是 `text/html`，就是这个文件根本没传上去（静态托管对不存在的文件常返回 200 + 首页 HTML，所以“不报错”）。

**一句话记忆**：**页面是照片，JS 是通电。照片能看，不代表通了电。**

> 当时我怎么想的：不熟悉静态站如何更新文件，上传时只能替换根目录文件，文件夹内文件无法替换，导致上传出错

## 3. `fetch` 遇到 404 / 500 不会报错

**现象**：故意把 API 地址写成错的，`catch` 里的“加载失败”不显示。

**原因**：`fetch` 只在**网络层失败**时才 reject（断网、域名不存在、跨域）。HTTP 状态码 404、500 都算“成功拿到了响应”。

**正确做法**：自己检查

```tsx
const res = await fetch(url);
if (!res.ok) {
  throw new Error("请求失败：" + res.status);
}
```

**一句话记忆**：**fetch 只保证“对方回话了”，不保证“对方说了好话”。**

> 当时我怎么想的：原来有状态码也算有响应

## 4. 点了「换一句」，句子没变

**现象**：逻辑全对，但连点几次还是同一句。

**原因**：接口被 CDN（Cloudflare）缓存了，同一个 URL 直接返回上次的结果。响应头里 `cf-cache-status: HIT` 就是证据。

**正确做法**：加一个每次都不同的参数，让 URL 变掉

```tsx
const res = await fetch("https://v1.hitokoto.cn/?_=" + Date.now());
```

**注意**：`fetch(url, { cache: "no-store" })` 只管浏览器缓存，管不到 CDN，不够用。

**一句话记忆**：**同一个地址，可能被中间人记住了。要新东西，就换个地址。**

> 当时我怎么想的：需要用随机来稍微改变URL才能每次请求都取到不一样的东西

## 5. Hook 写在组件外面 → `Invalid hook call`

**现象**：`useEffect` 放在文件顶部（组件外），页面红屏报 `Invalid hook call. Hooks can only be called inside of the body of a function component`。

**原因**：React 靠“调用顺序”记住每个组件的状态。组件外调用 Hook，React 不知道它属于谁。

**正确做法**：`useState` / `useEffect` 只能写在 `function Home() {` 和 `return` 之间，且不能在 `if`、`for` 里面。

**一句话记忆**：**Hook 是组件自己的房间，不能住到走廊上。**

> 当时我怎么想的：放错位置了，没放在框架里

---

## 6. 中文文件被脚本改完变成乱码

**现象**：用 PowerShell 的 `Get-Content` / `Set-Content` 批量替换时，中文变成 `鎴戠殑`。

**原因**：读取时的编码和写入时的编码不一致（UTF-8 被当成 GBK 读，再存成 UTF-8）。

**正确做法**：改带中文的文件用编辑器（VS Code）或专门的写入工具，别用 shell 的读写命令来回倒。

**一句话记忆**：**中文文件，手工改；脚本只用来搬运，不用来改字。**

> 当时我怎么想的：这应该是dsh犯的错误

## 7. 改动没生效，先怀疑三件事（不是代码）

按顺序排查，能省 80% 的时间：

1. **保存了吗**——VS Code 标签页上有个小白点就是没保存
2. **刷了吗**——浏览器缓存，Ctrl+F5；手机端清缓存或换浏览器
3. **传了吗**——Vercel 走 `git push` 自动，腾讯云要手动重传，两边容易不同步
